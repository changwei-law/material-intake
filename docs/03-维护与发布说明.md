# 维护与发布说明

> 最后更新：2026-10-06 ｜ 适用于 material-intake 0.2.15

---

## 一、仓库结构与分工

```
.
├── README.md            项目说明、能力概览、授权与工具速览
├── LICENSE              MIT
├── docs/                面向使用者与维护者的文档（不随技能安装）
└── material-intake/     技能本体（安装时复制这一个目录即可）
    ├── SKILL.md         主流程与命令（智能体读）
    ├── assets/          配置与台账模板
    ├── bin/             macOS EventKit 后端（arm64 二进制 + Swift 源码）
    ├── references/      细则文档（随技能分发，被 SKILL.md 引用）
    └── scripts/         Python 与 PowerShell 实现
```

**写入边界**：`docs/` 与 README 只在仓库层面维护；`references/` 内的文档会被 `SKILL.md` 以相对路径引用，**移动或改名会导致技能内断链**，改动前先确认引用关系。

## 二、改动纪律

1. **改脚本先跑语法检查**：`python3 -m py_compile material-intake/scripts/*.py`；PowerShell 脚本在 Windows 上用 `[System.Management.Automation.Language.Parser]::ParseFile()` 校验。
2. **改行为同步改文档**：脚本的参数、权限要求、写入位置一变，`SKILL.md`、`references/依赖与注意事项.md` 第六节与本仓库 `docs/01` 三处必须同步，避免出现「文档说十一处、实际十三处」这类自相矛盾。
3. **文档里的数量词要能对上表**：凡写「N 处授权」「N 件事」，改完立刻数一遍表格行数。
4. **不写平台外的绝对路径**：文档与脚本里一律用 `$SKILL`、`~/.material-intake/`、`%USERPROFILE%\` 这类占位写法。
5. **密钥与凭据永不入库**：钉钉 webhook、`.dws` 登录、任何 token 只允许存在于使用者本机。

## 三、发布流程

```bash
# 1) 本地改动完成后，跑语法检查与冒烟测试
python3 -m py_compile material-intake/scripts/*.py

# 2) 开源前体检（见第四节），确认全部为 0 命中

# 3) 提交并推送
git add -A && git commit -m "……"
git push

# 4) 需要发版时打标签并写 Release 说明
git tag -a v0.2.16 -m "material-intake 0.2.16"
git push origin v0.2.16
gh release create v0.2.16 --title "v0.2.16" --notes "变更要点……"
```

版本号的现行记录在技能包的《功能说明》与《技能介绍与使用说明》中；`SKILL.md` 的 frontmatter 不含 `version` 字段，因此**发版时须同步更新这两处文字**，不要只改 git tag。

## 四、开源前体检清单（每次推公开仓库前跑一遍）

以下命令把本机路径、组织标识与明文凭据当作模式来查。检查的是 **git 索引里的内容**，而不是工作目录——只有入库的东西才会被公开：

```bash
# 1) 本机绝对路径与用户名
git grep -In -E '/Users/[A-Za-z0-9._-]+|/home/[A-Za-z0-9._-]+|[A-Za-z]:\\\\Users\\\\[A-Za-z0-9._-]+' -- . || echo "OK"

# 2) 明文凭据（真实值，占位符如 access_token=xxx 不算）
git grep -In -E 'access_token=[A-Za-z0-9_-]{8,}|SEC[A-Za-z0-9]{12,}|ghp_[A-Za-z0-9]{20,}|sk-[A-Za-z0-9]{16,}' -- . || echo "OK"

# 3) 组织名、真实姓名、内网盘符等组织标识（按需补关键词）
git grep -In -E '替换为你需要屏蔽的组织标识' -- . || echo "OK"

# 4) 确认没有把内部件带进来
git ls-files | grep -E '内部|复验|回传|\.zip$|\.DS_Store$|打包|维护记录' || echo "OK"

# 5) 确认远端与本地的文件树一致（防止漏推或多推）
gh api repos/:owner/:repo/git/trees/HEAD?recursive=1 --jq '.tree[] | select(.type=="blob") | .path' | sort > /tmp/remote.txt
git ls-files | sort > /tmp/local.txt
diff /tmp/local.txt /tmp/remote.txt && echo "OK"
```

**从个人工作副本整理公开版时的必清项**（本仓库即按此整理）：开发与复验记录、内部维护文档、对外打包产物（zip）、系统文件（`.DS_Store`、`Thumbs.db`）、含本机用户名或内网盘符的路径、组织标识（含 Windows 通知身份之类的隐性标识）、写入脚本与文档中的真实姓名。

## 五、跨平台构建

- **`bin/lr_ek`（macOS）**：随包二进制为 arm64，最低系统 macOS 14.0。Intel Mac 使用者可用源码自行编译：

  ```bash
  swiftc -O -target x86_64-apple-macos14.0 material-intake/bin/lr_ek.swift -o material-intake/bin/lr_ek
  ```

  `schedule_write.py` 在后端缺失或源码更新时会自动尝试重编译（需要 Xcode 命令行工具），编译失败时给出提示并拒绝写入，不会静默降级。
- **Windows 脚本**：`.ps1` 无法在 macOS 上做语法校验，改动后须在 Windows 11（PowerShell 5.1）实机跑一次 `doctor` 与 `selftest`。
