# 平台差异对照：macOS 与 Windows

> 适用版本：material-intake 0.2.15 ｜ 最后更新：2026-10-06
> 依据：各脚本实现与 Windows 11 实机验证记录（2026-09-28）；核验日期 2026-10-06。

---

## 一、先记住一句话

两侧**不是同一功能的两种外观，而是两套能力不对等的实现**：

- **macOS**：一条命令闭环。`apply` 同时写系统日历与提醒事项，可读回、可按锚点精确撤销（EventKit 一套 API 管两件事）。
- **Windows**：没有 EventKit，用**五条通道拼出**接近效果，每条各有一个缺口，必须按场景选。

由此产生三类差异：**Windows 缺失的能力**、**同一目标实现方式不同**、**看起来同名但不等价的命令**。下文逐项说明。

## 二、能力矩阵

| # | 能力 | macOS | Windows | 差异性质 |
|---|---|---|---|---|
| 1 | 写系统日历 | ✅ EventKit 直写「日历」App，界面可见 | ⚠️ `win_calendar.ps1` 写 WinRT 日历存储，**系统界面上没有显示位置** | 实现不同 |
| 2 | 分档提醒 T-7／T-3／T-1／当天 | ✅ 写进「提醒事项」，四档是四条真提醒 | ⚠️ 系统日历存储**每条约会只支持一个提醒**，多档靠另建 4 条空闲条目模拟 | 实现不同 |
| 3 | 到点弹提醒的可靠性 | ✅ 由系统提醒事项托管 | ⚠️ 计划任务 + 系统通知；**关机或休眠期间到点不弹**，开机是否补弹由系统决定，不做保证；受专注助手影响 | **不对等** |
| 4 | 读回核对 | ✅ `list --days 60` 一条命令列出全部 | ⚠️ 分通道：`win_calendar.ps1 list`、`win_remind.ps1 list` 可读回；**`.ics` 导入的没有回读能力** | **不对等** |
| 5 | 按锚点撤销 | ✅ `rm --anchor`，事件与全部档位一并删除 | ⚠️ 分通道：日历与通知可撤销；**`.ics` 导入的只能在客户端按「来福ID:」手工搜索删除** | **不对等** |
| 6 | 周期性日程（每周例会一类） | ✅ EventKit 原生 `recurrenceRule`（日／周／月／年），且可删除周期事件 | ❌ `win_calendar.ps1` 与 `win_remind.ps1` **均无周期支持**；`.ics` 导出**不带 RRULE** | **Windows 缺失** |
| 7 | 待办清单 | ✅ 写进「提醒事项」清单 | ❌ 无等价物。替代：`win_remind.ps1` 到点弹通知，或用钉钉待办（出网） | **Windows 缺失** |
| 8 | 桌面日历里看得见 | ✅ 系统「日历」App | ⚠️ 需 `calendar_feed.ps1` 常驻订阅服务 + 桌面日历客户端（如 Thunderbird） | 实现不同 |
| 9 | 手机到点提醒 | ⚠️ 依赖 iCloud 同步日历／提醒事项 | ✅ 钉钉通道（**出网**，需自备凭据） | 各有取舍 |
| 10 | `.ics` 导出与导入 | ✅ | ✅（Windows 侧更常用，是首选通用通道） | 一致 |
| 11 | 需要的授权 | 日历 + 提醒事项**完全访问**（「仅写入」会使读与撤销失效） | 日历访问开关、通知总开关（系统级）、PowerShell 执行策略、计划任务、注册表 | 不同 |
| 12 | 会改动系统 | 无 | **3 项**：通知总开关、通知身份注册、订阅服务开机自启 | **Windows 独有** |
| 13 | 脚本文件编码要求 | 无特殊要求 | `.ps1` **必须 UTF-8 带 BOM**，否则 PowerShell 5.1 按 GBK 解析、中文报语法错误 | Windows 专有坑 |
| 14 | 联网 | 仅系统级 iCloud 同步 | 钉钉通道出网；订阅服务仅监听 `127.0.0.1` | 不同 |
| 15 | 环境要求 | macOS 14 及以上 | Windows 11 及以上（WinRT 日历行为随版本变化，换机器先跑 `doctor`） | 不同 |

## 三、想干一件事时，两侧分别怎么做

| 你的目标 | macOS | Windows | 建议 |
|---|---|---|---|
| 到点别忘 | 日历 + 提醒事项 `apply` | `win_remind.ps1` 系统通知 或 `.ics` 导入 | Windows 侧先走 `.ics`，需要"一定弹"再加系统通知 |
| 日历里要看得见 | 系统「日历」App | `.ics` 导入，或订阅服务 + 桌面客户端 | Windows 侧订阅服务只监听回环，不出网 |
| 必须能撤销 | `rm --anchor` | 日历／通知通道的 `rm` / `clear`；`.ics` 需手工删 | **别用 `.ics` 做要频繁改动的日程** |
| 手机上也要提醒 | 依赖 iCloud 同步 | 钉钉（出网） | 涉密案件改用 `.ics` 导到手机 |
| 重复日程（每月例会） | `recurrence` 字段，EventKit 原生周期 | 无周期能力：逐次生成，或导入后手工设为重复 | Windows 侧需人工补一步 |
| 涉密案件 | 本地全可用 | 系统通知 + `.ics`，**不要用钉钉** | 钉钉会让案号、法院、当事人出网 |

## 四、最容易坑人的三处差异

1. **撤销能力不对等**。macOS 任何一条写入都能按锚点撤销；Windows 走 `.ics` 导入的条目失去锚点回读能力，只能按正文里的「来福ID:」手工搜删。日程还会变的时候，别选 `.ics`。
2. **提醒可靠性不对等**。macOS 交给系统提醒事项；Windows 靠计划任务与系统通知，关机或休眠期间到点不弹，开机是否补弹由系统决定，**不做保证**。
3. **周期日程在 Windows 缺失**。需要重复日程时得逐次生成或手工设重复，`.ics` 也不含 `RRULE`。

## 五、为什么两侧会不一致

macOS 有 **EventKit**：一套 API 同时管日历与提醒事项，支持周期规则与精确删除。Windows 没有对等 API：日历存储是 WinRT 的 `Windows.ApplicationModel.Appointments`（每条约会只带一个提醒，且在系统界面上不可见），"到点弹"只能靠 `ScheduledToastNotification` 定时通知，周期规则与提醒清单都没有对等能力。

技能没有强行把两侧做成一个样子，而是各自用可用能力做到最接近，**并把缺口写在文档里**——缺的功能不假装成功：`schedule_write.py list/rm` 在 Windows 上按设计不可用，脚本会明说，而不是静默失败。

## 六、同名但不等价的命令（容易误解）

| 命令 | macOS | Windows |
|---|---|---|
| `schedule_write.py apply` | 真正写入日历与提醒事项 | **不适用**，请用 `ics` 导出或对应的 `.ps1` |
| `schedule_write.py list` / `rm` | 可用 | **按设计不可用**（依赖 EventKit） |
| `schedule_write.py ics` | 可用 | 可用，是 Windows 侧首选的通用通道 |
| `win_calendar.ps1` / `win_remind.ps1` / `calendar_feed.ps1` / `dingtalk_remind.ps1` | 不运行（Windows 专有） | 可用 |
| `lr_ek` / `bin/lr_ek.swift` | 核心后端 | 不适用（包内不随 Windows 分发） |

两侧对**同一条日程生成同一个锚点**（锚点算法逐字段一致），所以混用通道不会重复写入——这是刻意对齐的部分。差异只在"能做什么"，不在"认不认得同一条"。
