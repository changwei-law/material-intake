# 钉钉通道：开通前提与两条路径

> 适用版本：material-intake 0.2.15 ｜ 最后更新：2026-10-06
> 依据：钉钉开放平台官方文档《获取开发者权限》〔核验日期 2026-10-06〕；技能内 Windows 11 实机验证记录（2026-09-28）。

---

## 一、一句话结论

**钉钉通道不是「拿一个 webhook 填进去就能用」。** 它的前提是：**你在一个钉钉组织里有相应权限**。只有两条路：

| 路径 | 做法 | 是否需要管理员审批 |
|---|---|---|
| **A. 用现有组织**（如所在单位） | 让该组织管理员给你开发者权限，或你自己提交审批单由管理员批准 | **需要** |
| **B. 自建组织** | 在钉钉客户端「组织架构 → 创建或加入企业/团队」建一个自己的组织，你即主管理员 | **不需要**，自己就是管理员 |

若走不通，钉钉通道直接不可用；日程功能可退回 `.ics` 与本机通道，不影响台账与归档。

## 二、两类钉钉通道，要求不同

技能里有两个独立的钉钉通道，别混淆：

| 通道 | 脚本／工具 | 干什么 | 前置条件 |
|---|---|---|---|
| **钉钉提醒**（自定义机器人） | `dingtalk_remind.ps1` → `oapi.dingtalk.com/robot/send` | 到点往手机钉钉推一条消息 | 一个**能添加机器人的群** + 机器人 webhook（若开加签另需密钥）。组织内加机器人通常需群主／管理员操作，且组织安全设置可能限制机器人添加〔该项未逐句核验，见第六节〕 |
| **钉钉日历与待办** | 钉钉工作台 CLI `dws`／`dws-core` | 把日程写进**钉钉自己的日历与待办** | 一个**你有权限的钉钉组织** + 完成一次 `dws auth login`。用他人组织须管理员放行；自建组织无需 |

一句话记：**机器人 = 群权限问题，dws 日历待办 = 组织权限问题。**

## 三、路径 A：用现有组织（需管理员放行）

钉钉开放平台《获取开发者权限》给出的两条标准途径：

1. **管理员代为添加**：管理员登录钉钉管理后台 → **安全与权限 → 权限管理 → 子管理员 → 添加子管理员**，把你的账号配置为具备开发者权限（此项前提是：你已在该组织内、组织架构已搭好）。
2. **成员主动申请**：你自行登录开发者后台，在需要开发应用时按提示**提交子管理员审批单**，管理员审批通过后权限自动生效。

机器人一侧同理：组织若对群机器人添加做了安全设置限制，也需要管理员放行。

## 四、路径 B：自建组织（无需他人审批）

适合个人使用，或不愿动用单位组织的情况。钉钉官方文档写明：加入企业/团队的方式是**钉钉客户端 → 组织架构 → 创建或加入企业/团队**——也就是说，你可以自己创建一个组织并成为它的主管理员，此后开发者权限、机器人、工作台授权都由你自己掌握。

操作顺序（以 dws 写钉钉日历与待办为例）：

1. 钉钉客户端 → 组织架构 → 创建或加入企业/团队 → 建一个自己的组织；
2. 安装钉钉工作台 CLI：`npm i -g dingtalk-workspace-cli --registry=https://registry.npmmirror.com`（官方源在国内很慢）；若宿主已内置 `dws`／`dws-core`，可直接用；
3. `dws auth login`，选择刚建的组织完成授权；
4. `dws auth status` 核对 `corp_name` 与 `user_name` 是否为该组织与你本人；
5. 写一条测试日程，再用 `dws calendar +agenda` 读回核对（不要只信写入命令的返回，见第五节）；
6. 若还要钉钉提醒：在该组织的群里添加自定义机器人，取其 webhook 与加签密钥，跑 `dingtalk_remind.ps1 config` 与 `test`。

**为什么自建组织也能用**：钉钉日历与待办写的是**你本人在该组织下的个人数据**，与组织规模无关，个人组织同样具备〔工具推导，依据上表两条前置条件〕。

## 五、验证与常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `confirmation_required` | 非交互环境下写命令未加 `--yes`（连 `--dry-run` 也要加） | 追加 `--yes`，不要用管道喂答案绕过确认门禁 |
| 写入报「写后读回缺少字段 timeZone」，但事件其实已建成 | 已知误报 | 用 `dws calendar +agenda ... --format json` 读回核对，以读回为准 |
| `auth status` 显示未授权或身份不对 | 登录失效或选错组织 | 重新 `dws auth login`；多组织用 `--profile corpId:userId` 指定 |
| 组织里没有你的开发者权限 | 未获管理员授权 | 走路径 A 的两种方式之一，或改用路径 B 自建组织 |
| 机器人 `test` 报 `token is not exist` | webhook／加签密钥不对，或机器人被移除 | 重新在群里取 webhook 与密钥 |

## 六、风险与边界（必须事先告知使用者）

- **内容出网**：日程标题与时间会上传钉钉服务器，而标题按本工作流命名规则含**案号、法院、当事人**。涉密或不宜出网的案件，改用系统通知或 `.ics`；必须走钉钉时先用代号命名。
- **凭据不随包分发**：机器人 webhook 存 `%USERPROFILE%\.material-intake\dingtalk.json`，CLI 登录凭据存 `%USERPROFILE%\.dws\`；不要写进文档、聊天或压缩包。
- **自建组织不等于"数据留在本地"**：只是换了一个组织容器，数据仍在钉钉服务器上。
- **钉钉是 Windows 侧通道**（脚本为 PowerShell）：macOS 侧不运行 `dingtalk_remind.ps1`；需要在 macOS 上提醒，用系统日历／提醒事项或 `.ics`。
