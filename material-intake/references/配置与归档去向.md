# 配置与归档去向

## 一、配置文件位置

按以下顺序查找，命中即用：

1. 命令行 `--config <路径>`
2. 环境变量 `MATERIAL_INTAKE_CONFIG`
3. 当前目录 `.material-intake.json`
4. `~/.material-intake/config.json`

未找到配置时，先跑 `doctor` 看诊断结果，再 `init-config` 生成模板，然后按本机目录结构改。

## 二、配置字段

```json
{
  "workspace": "/绝对路径/00-材料代办录入",
  "dirs": {
    "inbox": "待处理",
    "work": "代办录入",
    "processed": "已处理",
    "pending": "待归档"
  },
  "archive_ledger": "归档台账.md",
  "allowed_roots": ["/绝对路径/案件库", "/绝对路径/客户顾问"],
  "dedupe_roots": ["/绝对路径/案件库"],
  "destinations": [
    {
      "label": "案件卷宗-诉讼",
      "path": "/绝对路径/案件库/【诉讼】某案/工作空间/",
      "keywords": ["起诉|答辩|传票|判决|裁定|证据"]
    },
    {
      "label": "可复用模板与 SOP",
      "path": "/绝对路径/02_文书模板/",
      "keywords": ["模板|sop|指引|清单"]
    }
  ]
}
```

| 字段 | 作用 | 缺省行为 |
|---|---|---|
| `workspace` | 工作区根目录 | 必填；未填时 `init` 需用 `--workspace` 指定 |
| `dirs` | 四个子目录名 | 用 `待处理／代办录入／已处理／待归档` |
| `archive_ledger` | 归档台账文件名，相对工作区 | `归档台账.md` |
| `allowed_roots` | 允许写入的根目录白名单 | 为空时 `archive` 拒绝执行 |
| `dedupe_roots` | 查重时默认搜索的库根 | 为空时需用 `--root` 指定 |
| `destinations` | 去向对照表，供给出建议路径 | 为空时只输出提示，由人工决定去向 |

`destinations[].keywords` 是正则片段，用 `|` 连接多个词，用于按文件名给出建议去向；可留空表示纯人工判断。

## 三、去向对照怎么填

对照表按使用者自己的目录结构填写，本技能不预设任何机构的内部结构。填法建议：

1. 先确定几个**归档根**（案件库、客户顾问、知识库、资源库），全部写进 `allowed_roots`。
2. 再按材料性质写 `destinations`，每条对应一个可以实际存放的目录，粒度到案卷子目录。
3. 同一性质的材料在不同案件下路径不同时，`destinations` 只写共性较强者，个案路径在对话中确认。

归档目标的硬性要求：目标目录必须落在 `allowed_roots` 之内，否则脚本拒绝写入。这条限制用于防止误写到系统目录或他人目录。

## 四、初始化步骤

```bash
# 1. 诊断
python3 "$SKILL/scripts/material_intake.py" doctor

# 2. 生成配置模板
python3 "$SKILL/scripts/material_intake.py" init-config --out ~/.material-intake/config.json

# 3. 编辑配置，填 workspace 与 allowed_roots

# 4. 再诊断一次，确认四个子目录与归档台账都在
python3 "$SKILL/scripts/material_intake.py" doctor
```

工作区四个子目录不存在时，按 `dirs` 的名字手工创建；`archive_ledger` 不存在时，用 `assets/归档台账模板.md` 的内容新建。
