# 安装与授权引导（给智能体执行）

本文件是**给智能体看的操作指令**，不是给用户读的说明书。用户装好本技能后，由你分阶段带着他完成授权；不要只丢一份文档让他自己看，也不要一次把全部授权抛给他。

## 一、三条纪律

1. **分阶段，一次最多引导两项**。按下面第二节的四档推进：装机档（零授权）→ 台账档 → 日程档 → 通知档。用不到的能力不必提前授权。
2. **每项四句话**：① 为什么要（用途）；② 点哪里、选什么（放行路径，含要勾选的应用名与权限档位）；③ 能不能拒绝、拒绝后用哪条替代路径；④ 复检（改完跑哪条命令）。
3. **不代点、不绕过**。系统授权只能用户本人在系统设置里点；任何代点、改注册表绕过、脚本模拟点击的做法一律不做。你的职责是把话说清、把路径给准、把复检做掉。

## 二、分阶段引导清单

| 档 | 触发条件 | 需要的授权 | 引导要点 | 复检命令 |
|---|---|---|---|---|
| 装机档 | 刚装好技能 | **无** | 明确告诉用户："这一步不需要给任何权限，台账、查重、归档、登记都能用。" | `python material_intake.py doctor`（应报「配置完整，可以开工」） |
| 台账档 | 用户要处理的材料在工作区以外（桌面／文稿／下载等） | macOS 文件与文件夹（必要时完全磁盘访问） | 说明只读取他指定的材料目录；拒绝时改为把材料先复制进工作区再处理 | 再跑一次 `doctor`；或直接重试 `scan` |
| 日程档 | 用户第一次要写日历／提醒 | macOS 日历＋提醒事项（**必须完全访问**，不能仅写入） | 强调"仅写入"会让查重与撤销失效，脚本会直接拒绝写入；拒绝时改用 `.ics` 导出（Windows）或改人工记入 | `python schedule_write.py doctor`（结论应为「读写通道均可用」） |
| 通知档 | 用户明确要"到点弹提醒" | Windows 通知总开关（**系统级，打开后所有应用的通知都会弹**）＋本机日历订阅（常驻服务＋开机自启）＋钉钉（凭据、出网） | 逐项说明影响范围与回退方法，得到同意再动；拒绝时退回系统通知以外的替代（`.ics` 导入手机日历） | 对应脚本的 `doctor`／`status` |

## 三、逐项引导话术模板

直接照着说，按用户的实际宿主把应用名换掉（Codex／WorkBuddy／千问办公）。

**① 日历与提醒事项（macOS，日程档）**

> 这一步需要 macOS 把日历与提醒事项权限给到「<当前宿主>」，我才能把开庭、期限写进你的日历并按 T-7／T-3／T-1／当天提醒。
> 请打开：系统设置 → 隐私与安全性 → 日历，勾选「<当前宿主>」，权限选**完全访问**（不要选"仅写入"，仅写入会导致我既查不了重、也撤不掉写进去的条目）；提醒事项同理。
> 如果你不想给：我就只做台账与归档，日程改用 `.ics` 导出，你自己导入日历。
> 改完回我一句，我重跑 `doctor` 复检。

**② 文件与文件夹（macOS，台账档）**

> 这批材料在桌面／文稿目录，macOS 默认不让应用读。请到 系统设置 → 隐私与安全性 → 文件与文件夹，允许「<当前宿主>」访问；如果材料分散在多个受保护目录，可能需要开「完全磁盘访问权限」。
> 不想开也行：把材料先复制进工作区，我照样能录。
> 改完我重试一次读取即可。

**③ Windows 通知总开关（系统级，通知档）**

> 这条会改动系统设置，请你先决定：`ToastEnabled` 从 `0` 改成 `1` 并重启用户通知服务后，**所有应用的通知都会开始弹出，不只是本技能**。如果你原本是有意关掉通知的，我们就不开，改用别的提醒方式（`.ics` 导到手机日历）。
> 同意的话我给出具体命令与回退方法（改回 `0` 即恢复静默）。

**④ 提醒身份注册（仅 Windows，通知档）**

> 需要在注册表写一个 `AppUserModelId` 并建一个开始菜单快捷方式，通知才能以本技能身份投递。回退命令是 `win_remind.ps1 uninstall`，不留残余。

**⑤ 钉钉通道（通知档）**

> 这条会把日程标题与时间上传到钉钉服务器，标题含案号、法院、当事人时属案件信息外发，**涉密案件不要用**。要用的话需要你自备钉钉机器人 webhook 或组织账号（CLI 本体由宿主自带或自行 `npm i -g dingtalk-workspace-cli` 安装，不随包分发），凭据只存本机。

## 四、用户拒绝时的降级表

| 被拒绝的授权 | 仍可用的能力 | 明确告知用户的取舍 |
|---|---|---|
| 文件与文件夹 | 把材料复制进工作区后，台账／查重／归档照常 | 多一步手工复制 |
| 日历／提醒事项 | 台账、归档、`.ics` 导出照常 | 不自动写入日历；无到点提醒 |
| Windows 通知总开关 | 系统通知通道不可用 | 改用 `.ics` 导到手机日历 |
| 钉钉 | 其余通道照常 | 手机端无钉钉提醒 |
| 全部拒绝 | **台账、查重、归档、登记全部可用** | 这是本技能的零授权模式，务必先讲清楚，避免用户以为不给权限就用不了 |

## 五、复检闭环

每引导完一项，立刻复检并把结果读给用户听（通过／未通过、还差什么），不要留到下次：

```bash
python material_intake.py doctor            # 归档侧：配置与目录
python schedule_write.py doctor             # 日程侧：读写通道（macOS）
```

Windows 侧另有：`win_calendar.ps1 doctor`、`win_remind.ps1 doctor`、`calendar_feed.ps1 status`。

## 六、附录：可选的一键打开设置（先验证再用）

部分宿主可以在得到用户同意后直接打开对应设置面板，省去用户找菜单的功夫。命令如下，**未在所有系统版本实测，使用前先在本机确认能跳到正确面板**：

```bash
# macOS
open "x-apple.systempreferences:com.apple.preference.security?Privacy_Calendars"
open "x-apple.systempreferences:com.apple.preference.security?Privacy_Reminders"
open "x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles"
```

```powershell
# Windows
start ms-settings:privacy-calendar
start ms-settings:notifications
```

即使用这条，也仍要向用户说明"要点哪一项、选哪一档"，不能点开面板就说"你自己弄"。

## 七、排查：系统根本不弹授权窗（macOS 14 及以上）

用户反馈"点了要用日历，但系统没有任何弹窗、直接就是没权限"，按以下顺序查，别急着让他反复点：

1. **是不是已经拒绝过**：系统对同一个应用只弹一次。去 系统设置 → 隐私与安全性 → 日历／提醒事项，看面板里有没有目标应用、当前档位是不是「仅写入」或已关闭。
2. **应用 Info.plist 是否声明了用途说明**（这是最容易被漏掉的根因）：macOS 14 起，应用申请日历／提醒事项**完全访问**时，自己的 Info.plist 必须声明 `NSCalendarsFullAccessUsageDescription` 与 `NSRemindersFullAccessUsageDescription`。缺这两个键时，系统**不弹窗、直接静默拒绝**，表现为"日程写入凭空不可用且看不出原因"。可用 `/usr/libexec/PlistBuddy -c "Print :NSCalendarsFullAccessUsageDescription" "<应用>/Contents/Info.plist"` 核查。
3. **是否被描述文件／MDM 限制**：机构统一下发的配置描述文件可以整体关闭日历访问，这种情况用户自己在设置里改不了，需要找 IT。

**如果确认是第 2 项（缺用途说明键）**：修法是给该应用的 Info.plist 补上两个键并重新签名。这属于**改动他人应用包**，原则上不随技能包附带自动脚本，须按下面三步走：

1. 先向用户说明：要改哪个应用、改什么键、会重新签名、原始 Info.plist 会先备份到 `~/material-intake-backups/`、如何还原；
2. 得到明确同意后，只在该用户的机器上执行，一次只改一个应用；
3. 改完必须复验：补键 → 重新签名并校验签名 → 重开该应用（不重开不生效）→ 再跑 `schedule_write.py doctor`。

不得把"代点授权""绕过 TCC""模拟点击"当作解决方案；补用途说明键是官方要求的正当做法，但改的是他人应用包，必须事前明示并取得同意。
