# 依赖与注意事项

新人拿到本包后，按本文件逐项核对，再开始使用。

## 一、运行环境

| 项目 | 要求 | 说明 |
|---|---|---|
| 宿主 | Codex 桌面版／CLI，或 WorkBuddy | 同一份技能两处通用，安装位置见 SKILL.md 第四节 |
| Python | 3.9 及以上 | 脚本仅用标准库；macOS、Linux 自带 `python3` 即可，Windows 需自行安装或用宿主内置运行时 |
| 磁盘 | 按材料体积预留 | 收件是复制副本，源材料与工作副本并存，空间约为原材料的 2 倍 |

技能包内不含任何案件数据、账号、密钥、内部制度文件，可直接对外分发；压缩包顶层的《技能介绍与使用说明.md》《功能说明.md》《使用与设置说明.md》说明安装与用法，收到即可用。

本技能由常威律师整理编制，使用与改进意见请反馈给编制人。

### 宿主差异

| 事项 | Codex | WorkBuddy |
|---|---|---|
| 用户级技能目录 | `~/.codex/skills/` | `~/.workbuddy/skills/`（旧版为 `~/.codebuddy/skills/`） |
| 项目级技能目录 | 无 | `<项目>/.workbuddy/skills/` |
| 插件形态 | 不使用插件形态，按普通技能安装 | 可选：`.workbuddy-plugin/plugin.json` 或 Claude 插件格式，清单请用宿主自带工具生成 |
| 写入限制 | 本技能的 `allowed_roots` 白名单 | 宿主沙箱另有可写范围，归档到工作区外需在设置中放行 |
| 技能管理 | 手工增删目录 | 手工增删目录；若要让宿主的 `skill_manage` 工具能改动能删除，须在 SKILL.md 增写 `agent_created: true` |

frontmatter 的取舍：本技能只保留两处校验器都接受的字段（`name`、`description`、`metadata`）。WorkBuddy 另认 `agent_created`、`disable`、`allowed-tools`，但 Codex 的校验器会拒绝 `agent_created` 与 `disable`，因此共用一份时不写；只给 WorkBuddy 用、且希望宿主智能体以后能自行维护时，再在 SKILL.md 里补 `agent_created: true`。

## 二、需自备的外接能力（均为可选）

不装也能用，只是相应环节需要手工完成或降级处理。

| 能力 | 缺省由谁承担 | 不装时的降级 |
|---|---|---|
| docx 解析 | 宿主内置文档能力或本地 python-docx | 转为 Markdown 后再读，或人工摘录 |
| xlsx 解析 | 宿主内置表格能力或本地 openpyxl | 导出 csv 后读 |
| pdf 文本层与页级处理 | 宿主内置 pdf 能力（依赖 Poppler、PyMuPDF 一类工具） | 有文字层的 pdf 可先转文本；无工具则人工摘录 |
| 扫描件／照片／截图取字 | OCR 或视觉识别技能 | 人工录入；注意不得在未授权情况下把客户材料上传外部接口 |
| 正式文书排版 | 排版技能（字体、字号、行距、页码） | 只交 Markdown 主稿，由使用者自行排版 |
| 法条现行有效性核验 | 使用者所在机构的法条核验通道 | 无法核验时，引用一律标注「待核验」，不作确定性表述 |

## 三、必须提醒使用者的十件事

1. **配置文件先改再用**。`allowed_roots` 为空时归档会被拒绝，这是有意设计，用于防止误写目录。
2. **归档只写白名单内**。脚本拒绝写入白名单之外的任何路径；岗位或团队目录调整后，先更新配置。
3. **默认不删除、不覆盖**。脚本不提供删除命令，同名文件一律报错而非覆盖；确需删除时由使用者手工执行并留痕。
4. **库外材料只读**。微信、桌面、下载目录里的原件不会被移动或改名，工作副本单独存放。
5. **收件会占双份空间**。大文件（上 GB 的卷宗）先确认磁盘余量，或改用手工方式只登记不复制。
6. **涉密材料先脱敏再外发**。对外分享、调用外部 OCR 或视觉接口前，先处理客户名称、证件号、账号、案号等标识。
7. **第三方接口的合规性由使用者负责**。是否允许把材料上传外部服务，取决于所在机构的保密规定与客户授权；本包默认不外传。
8. **台账摘要只写事实**。录入阶段不做证明力判断，判断留给承办律师；台账不是证据目录，不能直接作为举证清单使用。
9. **归档不等于定稿**。材料入卷前应由使用者确认归属与去向；脚本只执行已确认的动作，不替使用者作归属判断。
10. **日历权限必须给「完全访问」**。macOS 的「仅写入」下写入会成功但读取被拒，防重复与按锚点撤销同时失效，写进去的条目再也管不了。`doctor` 会实测读权限并在读不通时拒绝 `apply`；看到「已授权」不等于能读，以结论行为准。

## 四、跨系统差异

| 系统 | 可用性 |
|---|---|
| macOS | 全部功能可用；日程写入需在「系统设置 → 隐私与安全性」授予日历与提醒事项权限 |

WorkBuddy 在 Windows 上另有两处需现场确认：`python3` 是否在 PATH（不在则用宿主内置运行时，脚本路径不变）；归档根目录是否被宿主沙箱放行（未放行时脚本会在写入阶段被拦）。

## 五、排错

- 提示未找到配置：跑 `doctor` 看搜索了哪些路径，再用 `init-config` 生成并填写。
- 提示目标目录不在允许范围：把该目录加入 `allowed_roots`，不要绕开校验直接复制。
- 提示同名文件已存在：换用带日期或版本后缀的新名，不要加 `--force` 之外的方式强行覆盖。
- 查重过慢：缩小 `--root` 范围到具体案件目录；脚本按文件大小预筛，仍有大量同尺寸文件时会逐个哈希。
- 中文文件名乱码：确认终端编码为 UTF-8；脚本输出为 UTF-8 JSON 与 Markdown。
- 清单／配置文件编码：脚本**写入一律无 BOM**（JSON 规范不建议带 BOM）；**读取兼容带 BOM**（Python 用 `utf-8-sig`，PowerShell 用 `-Encoding UTF8`）。手工编辑后存成哪一种都不会导致解析失败——此前 Python 侧只认无 BOM、PowerShell 侧能吞 BOM，出现过「同一份清单 PS 能跑、Python 报错」的分裂，已修。

## 六、需要授权或会改动系统的十一处（放行路径与拒绝后果）

除 Windows 钉钉通道外，本技能不联网；以下十三处需要在本机系统或宿主里授权（其中 Windows 侧若干项会改动系统设置）。缺任何一项都不会静默失败：脚本要么打印放行路径，要么直接拒绝执行；宁可停住，不在半盲状态下写入。

| # | 授权项 | 何时出现 | 在哪里放行 | 拒绝后的表现 |
|---|---|---|---|---|
| 1 | 日历（**完全访问**） | macOS 首次写日程，或 `doctor` 探测读权限 | 系统设置 → 隐私与安全性 → 日历 → 勾选当前应用，选「完全访问」 | 写不进日历，且查重与撤销同时失效；`apply` 直接拒绝并给出放行路径 |
| 2 | 提醒事项（**完全访问**） | 同上 | 系统设置 → 隐私与安全性 → 提醒事项 | 分档提醒写不进去 |
| 3 | 文件与文件夹 | 读取桌面／文稿／下载等受保护目录 | 系统设置 → 隐私与安全性 → 文件与文件夹；跨目录批量操作需「完全磁盘访问权限」 | 扫描报错或列出被跳过的路径，其余目录照常 |
| 4 | 宿主沙箱可写范围 | WorkBuddy／千问办公归档到工作区以外 | 宿主设置里放行该目录 | 写入被宿主拦下 |
| 5 | Windows 日历访问 | Windows 直写本机日历 | 设置 → 隐私和安全性 → 日历 → 允许应用访问日历 | `win_calendar.ps1` 报错并给替代通道；`.ics` 通道不需要授权 |
| 6 | PowerShell 脚本执行策略 | 运行 `.ps1` | `-ExecutionPolicy Bypass -File` 单次放行，不必改全局策略 | 脚本被策略拦下 |
| 7 | macOS Gatekeeper | 首次双击 `.command` | 文件右键 → 打开；或 系统设置 → 隐私与安全性 → 仍要打开 | 双击无反应 |
| 8 | Windows SmartScreen | 首次运行下载来的脚本 | 选择「仍要运行」 | 脚本被拦下 |
| 9 | 宿主的库外读取确认 | 读取工作区以外的路径 | 宿主弹窗确认 | 该次读取失败 |
| 10 | **Windows 通知总开关**（系统级） | 需要在期限到点弹右下角通知时 | 设置 → 系统 → 通知 → 打开总开关（注册表 `HKCU\...\PushNotifications\ToastEnabled` 置 `1`） | ⚠ 打开后**所有应用**的通知都会弹，不只是本技能；不开则提醒不弹，日程仍写入 |
| 11 | **提醒身份注册**（注册表＋开始菜单快捷方式） | 首次使用通知提醒 | `win_remind.ps1 install`；回退 `win_remind.ps1 uninstall` | 通知无法以本技能身份投递 |
| 12 | **本机日历订阅服务**（常驻本地 HTTP＋开机自启计划任务） | 需要桌面日历客户端订阅日程时 | `calendar_feed.ps1 install`；回退 `calendar_feed.ps1 uninstall` | 客户端订阅不到；服务只监听 127.0.0.1，不出网 |
| 13 | **钉钉通道**（机器人 webhook 凭据；日程内容出网） | 需要手机钉钉提醒／钉钉日历时 | 自备钉钉机器人或组织账号：webhook 存 `%USERPROFILE%\.material-intake\dingtalk.json`，CLI 凭据在 `%USERPROFILE%\.dws\` ；**CLI 本体由宿主自带或自行 `npm i -g dingtalk-workspace-cli` 安装，不随包分发** | ⚠ **日程标题与时间会上传钉钉服务器**（可能含案号、法院、当事人）；涉密案件改用系统通知或 `.ics`。凭据不随包分发，对外分发时接收方需自备 |

不需要授权的情况：归档写入本技能自己的白名单目录；用 `ics` 导出后手动导入；纯台账、查重与扫描（前提是文件系统允许读）。Windows 上除日历外没有其他授权要求。

第 10、11 项会改动系统设置，执行前必须先向使用者明示「改什么、影响范围、怎么回退」，得到同意后再动；改完在汇报中说明改了哪一处。
