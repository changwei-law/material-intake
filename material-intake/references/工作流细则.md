# 工作流细则

本文件供录入、命名、分流、归档四个环节需要细节时查阅。SKILL.md 是主干，本文件是操作层。

## 一、命名规范

标准名统一为：`【案件简称】文件主题（日期）.扩展名`

- 案件简称放在最前的方括号内，同一案件全部一致（如 `【甲公司】`、`【张某】`）。企业全称过长时用简要字号，但同一案件不得混用两种简称。
- 文件主题写材料本身是什么（`开庭传票`、`证据清单及证据1-9`、`农行卡汇付明细`），不写判断、不写「关于」。
- 日期取材料本身载明的日期，格式 `YYYYMMDD`，放在圆括号内；材料无日期的写收件日期并备注说明。
- 案号、法院、审级等定位信息可放入主题内，用 `·` 分隔，例如 `证据清单（买卖合同·2026浙0102民初1号·20260927提交）`。
- 同一案件出现多份同类文书时，在主题后加限定词（`之一`、`初稿`、`修订版`），不要靠 `01`、`02` 编号区分内容。

原文件名一律保留在台账的「原文件名 → 标准名」列，改名不得覆盖、不得删除原件。

## 二、录入台账字段

| 字段 | 说明 |
|---|---|
| 序号 | 台账内顺序号，从 1 起 |
| 原文件名 → 标准名 | 左为收件时的原始名（含扩展名），右为按命名规范确定的标准名 |
| 类型 | 合同／裁判文书／诉讼证据材料／流水／函件／报表／清单／图片／其他 |
| 日期 | 文件本身载明的日期，不是接收日期；无则写「未载明」 |
| 内容摘要 | 三十字以内，只写事实不写判断。写「谁对谁做了什么、金额多少、共几页」，不写「该证据证明……」 |
| 归属 | 案件、客户、知识库或不适用；写具体案件全称或目录 |
| 建议去向 | 具体到子目录，不写到案件根目录为止 |
| 状态 | 待处理／已录入／待归档／已归档 |
| 备注 | 重复、缺页、无签章、待补材料、需核实事项 |

台账首部固定四行元信息：任务建立时间、来源（含接收路径与时间）、处理人、当前状态。

拆册材料（证据册、卷宗节选）在台账中另起一张对照表，标明「册内页码 ↔ pdf 页码」的换算关系，避免后续引用错页。

## 三、缺页、重复与材料不完整

- 收到疑似重复件：先做 SHA256 比对与文件名比对，结果写进备注，报告后再处理；同 SHA 视为同一件，不同 SHA 但内容雷同（如另存版本、扫描重拍）单独标注，由用户决定是否保留。
- 页码不连续、缺首尾页、无签章、无送达信息的，在备注列写明缺什么，并在「待办」中列为需补充材料。
- 无签章的摘录表、对账单等，属于来源要件不完整的材料：可以归档，但备注中必须写明「未列入现行证据目录，如需提交须补原件或调取凭证」。
- 大文件（数百 MB 以上、上千页）先做页级目录或文本索引，再决定是否逐页精读；索引放 `产出/`。

## 四、收件与分流的分界

| 材料来源 | 收件动作 | 处理完原件去向 |
|---|---|---|
| 工作区内的 `待处理/` | 复制进任务 `源文件/` | 原件移入 `已处理/` |
| 库内其他目录（如案件库、下载到库内的文件夹） | 只读，复制副本进 `源文件/` | 不动原件；需要归位时先报告 |
| 库外来源（微信、桌面、下载目录、U 盘） | 只读，复制副本进 `源文件/` | 不动原件 |

微信临时目录（`RWTemp`）等系统会自动清理的路径，原件无需处理，只需在台账中记录接收路径与时间。

## 五、与其他技能的配合

按需调用，不重复造轮子：

宿主不同，可用能力不同，现场有什么用什么：

- 需要生成正式文书：先起草 Markdown 主稿，再按使用者自己的排版规范出 docx。
- 需要读 pdf 页级内容、拆页、拼页：用宿主的 pdf 能力或本地工具。
- 需要读 xlsx 流水、做对账：用宿主的表格能力或本地工具；对账与验真另行走流水核对流程。
- 扫描件、照片、截图取字：走 OCR 或视觉识别能力。

缺少任何一项外接能力都不影响主体功能：台账、查重、归档、登记照常执行，缺的那一项走人工并在备注中写明。

## 六、汇报模板

汇报按四段写，不写过程日志：

1. 来源：谁在什么时候、通过什么渠道给了什么，共几件、什么形态（截图／pdf／压缩包／文件夹）。
2. 去向：逐件列出目标路径；未获确认的写「待确认：<建议路径>」。
3. 状态：已录入／已归档／已登记，重复件与缺件一并说明。
4. 待办：需要用户决定或补充的事项，按紧急度排序，写明截止时间。

## 七、收尾沉淀

任务结束时回看一遍：本次确认了哪些命名与去向惯例、哪些命令与路径可复用、哪些坑要避免、哪些材料还等后续补齐。稳定的结论再写入工作区约定文件，不要写进临时记录。
